# Phase 1 · 规范与受众定义

入场条件：无。

**停等点**：先问两件事并等回答。

```
1. 这份 PPT 给谁看？（如客户老板、内部管理层、投资人）
2. 看完后希望他们做什么决定或行动？
```

## 步骤

**1. 固定数值**：读 `style-tokens.md`。字号、颜色、线宽、圆角和页面框架按该文件，全册不变。
用户或客户另有品牌色时，替换语义色的色值，含义和用法不变，替换记进基线。

**2. 需求收集**：能推断的不问，要问的一次问完。

| 字段 | 规则 |
| --- | --- |
| 主题、受众 | 必须用户给 |
| 汇报目标 | 客户→说服；内部→汇报；外部会议→展示 |
| 期望页数 | 未指定时汇报类默认 12 页，方案类默认 50 页 |
| 用户材料 | 没有材料时提醒质量会下降 |
| 交付模式 | 现场讲→presenting；带走读→reading；两者都要→hybrid（默认） |
| 文稿类型 | 售前方案、规划方案、项目方案→方案；其余→汇报（默认）。方案再定形态：通用方案、项目方案、整体规划方案 |
| 输出 | 网页预览加可编辑 PPTX（默认）；用户只要其一时按用户 |

文稿类型为「方案」时读 `solution-deck.md`，并向用户要项目术语表（客户系统、我方交付物、场景）。

全部文稿类型开工时都建项目色表和术语表，写进基线：

- 色表默认取 `style-tokens.md` 第二节的三个语义色。汇报类可改含义，项目确需第四色时注明含义。
- 术语表每个事物写一个标准名，并列出不允许的写法。

**2.1 项目配置**：按色表和术语表生成工作区的 `项目配置.json`，供 Phase 8 的 `check_deck.py` 使用。格式见
`assets/tools/check_deck.example.json`：`accents` 写语义色和含义，`terms` 写标准名和不允许的写法，
`watch` 写不应出现的名称（如其他客户的简称）。色表或术语表后来有变动时同步改这个文件。

**3. 受众卡**：

```
受众：职位或角色
关心：核心关切 1 / 核心关切 2
预期行动：看完后要做的决定
主要顾虑：最可能提的反对意见
次要受众（可选）：同场有否决权的人
否决点（可选）：次要受众可能否决的理由
```

**4. 档位检测**：执行 `coach-engine.md`「Phase 1 末尾：初始检测」的三道题，记入基线。
