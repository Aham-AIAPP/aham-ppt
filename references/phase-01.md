# Phase 1 · 规范与受众定义

入场条件：无。

**停等点**：先问两件事并等回答。

```
1. 这份 PPT 给谁看？（如客户老板、内部管理层、投资人）
2. 看完后希望他们做什么决定或行动？
```

## 步骤

**1. 品牌规范**：读 `brand-spec/brand.md` 的配色、字体和 PPT 两节，记为 BRAND_RULES。
文件不存在时用 SKILL.md 的「降级基线」，并告诉用户。

**2. 需求收集**：能推断的不问，要问的一次问完。

| 字段 | 规则 |
| --- | --- |
| 主题、受众 | 必须用户给 |
| 汇报目标 | 客户→说服；内部→汇报；外部会议→展示 |
| 期望页数 | 未指定默认 12 页 |
| 用户材料 | 没有材料时提醒质量会下降 |
| 交付模式 | 现场讲→presenting；带走读→reading；两者都要→hybrid（默认） |
| 文稿类型 | 售前方案、规划方案、项目方案→方案；其余→汇报（默认）。方案再定形态：通用方案、项目方案、整体规划方案 |
| 输出 | 网页预览加可编辑 PPTX（默认）；用户只要其一时按用户 |

文稿类型为「方案」时读 `solution-deck.md`，并向用户要项目术语表（客户系统、我方交付物、场景）。

全部文稿类型开工时都建项目色表：每种颜色一个含义，写进基线。

**3. 受众卡**：

```
受众：职位或角色
关心：核心关切 1 / 核心关切 2
预期行动：看完后要做的决定
主要顾虑：最可能提的反对意见
次要受众（可选）：同场有否决权的人
否决点（可选）：次要受众可能否决的理由
```

**4. 档位检测**：执行 `coach-engine.md`「Phase 1 末尾：初始检测」的三道题，记入基线。

## 完成卡字段

BRAND_RULES 来源、受众卡、档位、交付模式、文稿类型和形态、输出、期望页数、色表。
