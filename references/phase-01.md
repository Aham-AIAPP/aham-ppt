# 阶段 1 · 受众与规范

入场条件：无。

**停等点**：先问两件事并等回答。

```
1. 这份 PPT 给谁看？例如客户老板、内部管理层、投资人。
2. 看完后希望他们做什么决定或行动？
```

## 步骤

**1. 读固定数值**：读 `style-tokens.md`。字号、颜色、线宽、圆角和页面框架按该文件，全册不变。
用户另有品牌色时，替换语义色的色值，含义和用法不变，替换记进基线。

**2. 收集需求**：能推断的不问，要问的一次问完。

| 字段 | 规则 |
| --- | --- |
| 主题、受众 | 由用户给出 |
| 汇报目标 | 给客户看定为说服；给内部看定为汇报；外部会议定为展示 |
| 页数 | 用户未指定时，汇报类 12 页，方案类 50 页 |
| 材料 | 没有材料时提醒用户成稿质量会下降 |
| 交付模式 | 现场讲定为 presenting；带走读定为 reading；两者都要定为 hybrid（默认） |
| 文稿类型 | 售前方案、规划方案、项目方案定为方案，其余定为汇报（默认）。方案再定形态：通用方案、项目方案、整体规划方案 |
| 输出 | 网页预览加可编辑 PPTX（默认）。用户只要其中一种时按用户 |

文稿类型为方案时读 `solution-deck.md`，并向用户要项目术语表：客户系统、我方交付物、场景。

**3. 建色表和术语表**，写进基线：

- 色表默认用 `style-tokens.md` 第二节的三个语义色。汇报类可以给三色另定含义。项目确需第四色时注明含义。
- 术语表给每个事物写一个标准名，并列出不允许的写法。

**4. 生成项目配置**：按色表和术语表写工作区的 `项目配置.json`，格式见 `assets/tools/check_deck.example.json`。
`accents` 写语义色和含义，`terms` 写标准名和不允许的写法，`watch` 写不应出现的名称，例如其他客户的简称。
`title_style` 方案类写 `noun`，汇报类写 `conclusion`。
色表或术语表有变动时同步改这个文件。

**5. 写受众卡**：

```
受众：职位或角色
关心：核心关切 1 / 核心关切 2
预期行动：看完后要做的决定
主要顾虑：最可能提出的反对意见
次要受众（可选）：同场有否决权的人
否决点（可选）：次要受众可能否决的理由
```

**6. 检测档位**：按 `coach-engine.md` 第二节的三道题检测，结果记入基线。

## 完成卡字段

受众卡、档位、交付模式、文稿类型和形态、输出、页数、色表、术语表、`项目配置.json` 路径。
待确认：受众画像是否准确，有没有遗漏的关切。
