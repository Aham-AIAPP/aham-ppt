# 阶段 2 · 材料解析

入场条件：阶段 1 已确认。

**停等点**：本阶段的信息清单与阶段 3 的灵魂句一起确认，不单独停等。
两种情况要停下问用户：用户没给任何材料时，问是否补材料；关键数据有冲突时，按步骤 5 请用户裁决。

## 步骤

**1. 先出提纲再读原文**

```bash
python assets/tools/extract_outline.py <材料文件...> --out 材料提纲/
```

脚本把 PDF、Word、PPT、Excel 和 Markdown 转成提纲：章节标题、位置、每节字数、含数字的句子和表格。
对照受众卡的关切和汇报目标，在提纲里圈出相关章节，只读这些章节的原文。
材料超过 50 页时可以交给子代理按提纲读，只把清单行传回。

**2. 写信息清单**：一条一行，写进 `基线.md`。

```
| 编号 | 类型 | 内容 | 出处 |
| D03 | 数据 | 年维护工单约 240 个 | 运维报告.pdf p12 |
```

- 类型四种：事实 F、数据 D、问题 P、结论 C。C 只收材料里已有的判断。
- 数据写数值、单位、时间和出处。
- 后续阶段只引编号，不回读原文。

**3. 补空缺**

- 对照受众卡标出空缺，分三类：关键空缺、一般空缺、无法补充。关键空缺不补就撑不起论点。
- 只为关键空缺搜索，全阶段最多 3 次。只打开要引用数字的页面，记下机构名和发布时间。
- 来自模型知识的内容标「[模型知识，建议核实]」。不确定的内容记进待确认清单，不编造。

**4. 剔除**：与汇报目标和受众关切无关的背景、技术细节和重复信息不进清单。

**5. 登记冲突**：关键事实或数据有冲突时，列出双方、各自出处和建议采信的一方，一手材料优先。
请用户裁决。未裁决的冲突留在本阶段，不进入阶段 3。

## 处理材料的方法

- 优先用原始转写和原文，二手纪要只作参考。
- 涉及工艺、流程、防错时，先确认对象的实际形态，例如人工还是自动。推断的细节标「[待调研]」。
- 不暗示否定客户已有的规划。价值用客观的排序和结构表达，不写自夸口号。
- 脱敏：人名换成角色，第三方公司名换成「某企业」。

## 完成卡字段

不单独出完成卡。清单条数、关键空缺、冲突裁决结果并入阶段 3 的完成卡。
