# Phase 2 · 材料解析

入场条件：Phase 1 已确认。

**停等点**：本阶段不单独停等。信息清单与 Phase 3 的灵魂句一起确认。
只有两种情况要停：用户没给任何材料（问是否补材料），关键数据有冲突（见步骤 5）。

## 步骤

**1. 先出提纲再读**

```bash
python assets/tools/extract_outline.py <材料文件...> --out 材料提纲/
```

脚本把 PDF、Word、PPT、Excel 转成提纲：章节标题、页码、每节字数、含数字的句子和表格。
对照受众卡的关切和汇报目标，在提纲里圈出命中的章节，只读这些章节的原文。
材料超过 50 页时可交给子代理按提纲读，只把清单行传回。

**2. 写信息清单**：一条一行，写进 `基线.md`。

```
| 编号 | 类型 | 内容 | 出处 |
| D03 | 数据 | 年维护工单约 240 个 | 运维报告.pdf p12 |
```

- 类型四种：事实 F、数据 D、问题 P、结论 C。C 指材料里已有的判断，不是 AI 的判断。
- 数据带数值、单位、时间和出处。
- 后续阶段只引编号，不回读原文。

**3. 补空缺**

- 对照受众卡标出空缺：关键空缺（不补撑不起论点）、一般空缺、无法补充（接受并标注）。
- 只为关键空缺搜索，全阶段最多 3 次。只打开要引用数字的页面，记机构名和发布时间。
- 模型知识标「[模型知识，建议核实]」。不确定的写「[待确认]」，不编造。

**4. 剔除**：与目标和受众关切无关的背景、技术细节、重复信息不进清单。

**5. 冲突登记**：关键事实或数据有冲突时列出双方、各自出处和建议采信项（一手材料优先），
请用户裁决。未裁决不进入 Phase 3。

## 内容方法

- 一手材料优先：用原始转写和原文，不只信二手纪要。
- 涉及工艺、流程、防错时，先确认对象的真实形态（人工还是自动），推断的细节标「[待调研]」。
- 不暗示否定客户既有规划。价值用客观排序和结构表达，不写自夸口号。
- 脱敏：人名换角色，第三方公司名换「某企业」。

## 完成卡字段

不单独出完成卡。清单条数、关键空缺、冲突裁决结果并入 Phase 3 完成卡。
