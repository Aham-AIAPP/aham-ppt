# 阶段 7 · 逐页设计

入场条件：阶段 6 的视觉基调已确认。

**停等点**：开始前告诉用户写页顺序和每章确认一次的安排，用户同意后开始。

## 步骤

**1. 每章开工前**：重读 `design-principles.md` 第一节、范例库说明和基线里的修正记录。

**2. 逐页写**：按页码顺序，每页按规划卡的内容结构和图形设计写进 `build.js`。
坐标按本页内容定，可以偏离规划卡的草图。同类元素用同一个组件函数，尺寸和间距与样页一致。

**3. 每页写完**：运行生成和 `check_slides.js`，看截图。ERROR 当页改完。填七项自查表，写进 `骨架.md` 该页下方。

**4. 每章确认一次**：一章写完后给用户看预览和该章的自查表。用户有意见时先记修正记录，再改页面。

**5. 全册预览**：全部写完后生成预览页，用 `check_slides.js` 的 `--sheet` 生成缩略图总览，检查三项：

- 相邻页的主图结构不同，同结构的两页画法不同。
- 同一概念全册同一名称，同一颜色全册同一含义。
- 没有风格与其他页明显不同的页。

**6. 导出**

```bash
node assets/html2pptx/html2pptx.js deck/ 交付/<文件名>.pptx --title "<标题>" --author "<作者>"
```

讲稿写在各页的 `<aside>` 里，导出后进 PPT 备注。导出结果有问题时改 `build.js` 再导出，不直接改 PPTX。

## 七项自查表

每一项写看到的内容，不只打勾。写不出内容的项按未检查处理。

| 项 | 写什么 | 例 |
| --- | --- | --- |
| 结构 | 遮住标题后，图形表达的结构和画法 | 时间压缩，双泳道加尺寸线 |
| 元素含义 | 每种颜色、线型、标记代表什么，图例在哪 | 蓝色是 AI 步骤；虚线框是后续场景；图例在右下 |
| 密度 | 单名称方框和无标签箭头的个数及理由 | 单名称方框 0 个；无标签箭头 2 个，只表示先后 |
| 相邻页 | 前后两页的结构名 | 前页来源与去向，后页界面说明 |
| 同组格式 | 本页同类元素的组数，加粗、间距、标签位置是否一致 | 泳道标签都在色条右侧 |
| 文字 | 子标题与页内是否重复；页面短句是否只有一个分句 | 无重复；属性带 4 项都是名词短语 |
| 检查结果 | 自动检查的条数和保留项的理由 | WARNING 0 条；INFO 1 条，矩阵格子只写名称 |

## 修正记录

用户每指出一处问题，先在 `基线.md` 的修正记录里记一条，再改页面。

| 原话 | 抽象规则 | 反例 | 影响的页 |
| --- | --- | --- | --- |
| 用户的原话，照录 | 改写成适用于其他页的规则 | 出问题的页和元素 | 按这条规则在全册查出的页 |

记下后按抽象规则查全册，同类问题一起改。
