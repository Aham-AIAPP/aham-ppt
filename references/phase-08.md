# 阶段 8 · 质检交付

入场条件：阶段 7 的全册预览已确认，PPTX 已导出。

**停等点**：质检报告输出后停等，由用户决定 WARNING 的处理方式。

ERROR 必须改完才能交付。WARNING 由用户选择修复、带注释交付或忽略。INFO 只作提示。

## 步骤

**1. 机器检查**

```bash
node assets/html2pptx/check_slides.js deck/ --png 交付/png
python assets/tools/check_deck.py 交付/<文件名>.pptx --config 项目配置.json --out 交付/自查报告.md
```

- `check_slides.js` 查字号、溢出、越界、重叠、导出兼容，以及文字越框、压线、对比度、箭头标签、单名称方框和空白。
- `check_deck.py` 查最小字号、逗号分句、禁用词、页码引用、内部编号、编号跳号、术语、价格说法、标题形式、颜色和图例。
  它还输出标题通读表、页码引用表和数量说法表，供人工核对。

**2. 人工检查**

| 层 | 检查项 |
| --- | --- |
| 叙事 | 标题连读指向灵魂句；执行摘要含 SCQA 的答案；受众的每项关切有对应页；标题的每个断言有页内证据，标题强于证据时判 ERROR；一页一个信息 |
| 文字 | 按 `wording-rules.md` 第六节检查；数量说法逐一实数；符号有图例；超过 60 字的句子拆开 |
| 版式 | 按 `design-principles.md` 七条原则逐条检验；逐页做遮标题检验 |
| 交付 | 数据有出处（方案类写在讲稿）；封面有委托方、版本和日期；没有真实人名和第三方公司名；页数与骨架一致 |

方案类再按 `solution-deck.md` 6.2 的清单逐条检查，按 6.3 写修改记录。

**3. 渲染抽查**：LibreOffice 可用时把 PPTX 转成 PDF，抽 3 页与网页截图比较换行和位置。
没有 LibreOffice 时跳过，并在交付说明里写明。

**4. 修正记录升级**：列出基线里的修正记录，逐条问用户要不要升级为技能的通用规则。
用户同意的条目，写明建议修改的技能文件和条文，由用户决定是否提交到技能仓库。

**5. 质检报告**：按 ERROR、WARNING、INFO 分列，每条写页码、问题和修改建议，最后列出已通过的项。

**6. 交付**

| 文件 | 说明 |
| --- | --- |
| `<文件名>.pptx` | 可编辑 PPT，讲稿在备注里 |
| `<文件名>.pdf` | 从 PPTX 导出；没有 LibreOffice 时不出 |
| `preview.html` | 网页预览，可分享 |
| `deck/`、`build.js` | 页面源文件，后续改版用 |
| `自查报告.md`、修改记录 | 质检结果和已知问题 |

交付说明写明机器检查覆盖不到的两项：每页内容是否有说服力，叙事角度是否符合受众的决策方式。这两项由用户判断。

## 完成卡字段

交付物清单、ERROR 修复数、WARNING 处理方式、已知问题。
