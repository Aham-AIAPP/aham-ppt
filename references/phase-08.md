# Phase 8 · 质检与交付

入场条件：Phase 7 全册预览已确认，PPTX 已导出。

**停等点**：质检报告出来后停，等用户决定 WARNING 的处理方式。

ERROR 阻断交付；WARNING 由用户选修复、带注释交付或忽略；INFO 只提示。

## 步骤

**1. 机器检查**

```bash
node assets/html2pptx/check_slides.js deck/ --png 交付/png      # 字号、溢出、越界、重叠、导出兼容、设计检查
python assets/tools/check_deck.py 交付/<文件名>.pptx --config 项目配置.json --out 交付/自查报告.md
```

`check_deck.py` 查最小字号、逗号分句、禁用词、页码引用、内部编号、编号跳号、术语表、
单页颜色数和图例，输出标题通读表、页码引用表、数量说法表。ERROR 必须改完。

**2. 人工检查**

| 层 | 检查项 |
| --- | --- |
| 叙事 | 标题串读指向灵魂句；执行摘要含 SCQA 的答案；受众关切都有对应页；标题的每个断言有页内证据，标题强于证据判 ERROR；一页一个信息 |
| 文字 | 按 `wording-rules.md` 第六节自查；数量说法实际数一遍；符号有图例；单句超过 60 字拆开 |
| 版式 | 按 `design-principles.md` 七条原则逐条检验；遮标题检验逐页过 |
| 交付 | 数据有出处（方案类写讲稿）；封面有委托方、版本、日期；无真实人名和第三方公司名；页数与骨架一致 |

方案类再按 `solution-deck.md` 6.2 的清单逐条过，按 6.3 写修改记录。

**3. 渲染抽查**：LibreOffice 可用时把 PPTX 转 PDF，抽 3 页与网页截图对比换行和位置。
没有 LibreOffice 时跳过并在交付说明里记一笔。

**4. 修正记录升级**：列出基线里的修正记录，逐条问用户要不要升级为技能的通用规则。
用户同意的条目，写明建议改动的技能文件和条文，交给用户决定是否提交到技能仓库。

**5. 质检报告**：按 ERROR、WARNING、INFO 分列，每条写页码、问题和修改建议，最后列已通过的项。

**6. 交付**

| 文件 | 说明 |
| --- | --- |
| `<文件名>.pptx` | 可编辑 PPT，讲稿在备注里 |
| `<文件名>.pdf` | 从 PPTX 导出；没有 LibreOffice 时不出 |
| `preview.html` | 网页预览，可分享 |
| `deck/` | HTML 源文件，后续改版用 |
| `自查报告.md`、修改记录 | 质检结果和已知问题 |

交付说明写明机器检查管不到的部分：每页内容是否有说服力、叙事角度是否契合受众的决策逻辑，由用户判断。

## 完成卡字段

交付物清单、ERROR 修复数、WARNING 处理方式、已知问题。
