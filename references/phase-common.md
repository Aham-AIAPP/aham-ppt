# 阶段公共规则

> 进入 Phase 1 时加载一次，八个阶段共用。各 `phase-0N.md` 只写本阶段的入场条件、停等点、步骤和完成卡字段。

## 一、每个阶段的固定动作

1. 进入第 N 阶段前读 `phase-0N.md`，第一句输出 `【阶段 N/8 · 阶段名 · 已加载 phase-0N.md】`。
2. 核对入场条件。上一阶段未确认时回到上一阶段。
3. 档位为引导或教练时，读 `coach-engine.md` 第三节里本阶段的引导序列并执行。专家档不读。
4. 执行阶段文件的「停等点」：向用户提问并等回答，再做步骤。
5. 做完步骤，输出完成卡并等用户确认，再进入下一阶段。

停等合并规则见 `coach-engine.md`「停等卡点合并」。合并只减少停等次数，不减少任何测试和检查项。
Phase 3（灵魂句）和 Phase 6（样页）在任何档位都单独停等。

## 二、完成卡格式

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
✅ Phase N · 阶段名 完成
本阶段输出  [阶段文件「完成卡」列出的字段]
关键结论    [一到三行]
待确认      [请用户确认的问题]
确认后进入 Phase N+1 · 下一阶段名。需要修改请直接说明。
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

## 三、用户要求跳过某阶段时

先说明跳过的后果，用户坚持再跳过，并在 Phase 8 的交付说明里记一笔。

| 阶段 | 跳过后果 |
| --- | --- |
| 1 受众 | 论点不针对受众关切，全册方向偏 |
| 2 材料 | 论点缺证据，数字无出处 |
| 3 灵魂句 | 全册没有主张，标题串读只剩话题 |
| 4 骨架 | 内容变成流水账，Phase 8 叙事检查大量返工 |
| 5 规划 | 设计时即兴定版式，内容与图形不匹配 |
| 6 样页 | 风格不满意时要改全部页面 |
| 7 设计 | 不可跳过 |
| 8 质检 | 不可跳过 |

## 四、工作区文件

| 文件 | 写入阶段 | 用途 |
| --- | --- | --- |
| `基线.md` | 1–7 | 受众卡、档位、交付参数、色表、术语表、信息清单、灵魂句、待确认清单、修正记录 |
| `项目配置.json` | 1 | 色表和术语表的机器可读版，供 `check_deck.py` 使用 |
| `材料提纲/*.md` | 2 | 提纲脚本的输出，只读命中章节时用 |
| `骨架.md` | 4–5 | Ghost Deck 和逐页规划卡 |
| `deck/` | 6–7 | 网页幻灯片，结构见 `html-slides.md` |
| `交付/` | 8 | PPTX、PDF、预览页、自查报告、修改记录 |

后续阶段引用基线里的编号，不回读原始材料。同一客户再做时先读已有的 `基线.md`，只解析新增材料。
