# 阶段公共规则

八个阶段共用本文件。各阶段文件只写入场条件、停等点、步骤和完成卡字段。

## 一、每个阶段的固定动作

1. 读本阶段文件，第一句输出 `【阶段 N/8 · 阶段名 · 已读 phase-0N.md】`。
2. 核对入场条件。上一阶段没有确认时回到上一阶段。
3. 档位为引导或教练时，执行 `coach-engine.md` 第三节里本阶段的引导序列。专家档跳过这一步。
4. 执行停等点：向用户提问并等回答，再做步骤。
5. 做完步骤后输出完成卡，等用户确认再进入下一阶段。

停等次数按 `coach-engine.md` 第二节合并。合并只减少停等次数，各项测试和检查照常做。
第三阶段的灵魂句和第六阶段的样页在任何档位都单独停等。

## 二、完成卡格式

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
✅ 阶段 N · 阶段名 完成
本阶段输出  阶段文件「完成卡字段」列出的内容
关键结论    一到三行
待确认      请用户确认的问题
确认后进入阶段 N+1 · 下一阶段名。需要修改请直接说明。
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

## 三、跳过阶段

用户要求跳过某阶段时，先说明后果。用户坚持就跳过，并在交付说明里记一笔。

| 阶段 | 跳过的后果 |
| --- | --- |
| 1 受众与规范 | 论点不针对受众的关切，全册方向偏 |
| 2 材料解析 | 论点缺证据，数字没有出处 |
| 3 论点提炼 | 全册没有主张，标题连读只剩话题 |
| 4 叙事骨架 | 内容按材料顺序堆放，质检时大量返工 |
| 5 页面规划 | 写页时临时定图形，图形与内容不匹配 |
| 6 样页确认 | 风格不满意时要改全部页面 |
| 7 逐页设计 | 不可跳过 |
| 8 质检交付 | 不可跳过 |

## 四、工作区文件

| 文件 | 写入阶段 | 内容 |
| --- | --- | --- |
| `基线.md` | 1–7 | 受众卡、档位、交付参数、色表、术语表、信息清单、灵魂句、待确认清单、修正记录 |
| `项目配置.json` | 1 | 色表和术语表的机器可读版，供 `check_deck.py` 使用 |
| `材料提纲/` | 2 | 提纲脚本的输出 |
| `骨架.md` | 4–7 | 标题序列、逐页规划卡、每页自查表 |
| `build.js` | 6–7 | 页面生成脚本 |
| `deck/` | 6–7 | 网页幻灯片，结构见 `html-slides.md` |
| `交付/` | 8 | PPTX、PDF、预览页、自查报告、修改记录 |

后续阶段引用基线里的编号，不回读原始材料。同一客户再做时先读已有的 `基线.md`，只解析新增材料。
