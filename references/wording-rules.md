# 用词规则

适用于本技能生成的 PPT 全部文字：标题、子标题、分区小标题、导语、并列信息格、列表、图内文字、卡片和说明句。
方案类的标题、子标题和页面短句另按 `solution-deck.md` 第三、五节。
例子里的公司名和模块名都是占位符，写作时换成项目的实际名称。

## 一、总则

### 1.1 一句话的标准

每句话告诉一位具体的读者一件事。描述话题和讲道理都不合格。

判断不准时回到这一条。描述话题的句子写成名词短语；讲道理的句子写成格言和对话腔。

### 1.2 两类失败

只挡住话题词，句子会转向格言。两类都要挡住。

```
话题词      现场数据自动化
            没有动词，读者不知道谁做、做完是什么结果

格言        外部追问每年都会来，取数成本取决于数据是不是同一套
            有主谓，主语是抽象名词，句子在讲道理

合格        〈报表模块〉可按六个披露方向输出数据与追溯记录
```

### 1.3 对话与交付物分开

对话里的口头分析不搬进交付物。对话可以用口语，页面不用。

## 二、结论式标题

汇报类的页标题写成结论。方案类的页标题写名词短语，本节规则改为检验子标题，见 `solution-deck.md` 3.2。

### 2.1 主语

主语是可以指认的对象，只有三类：

| 类别 | 说明 | 占位示例 |
| --- | --- | --- |
| 系统 | 本次交付的系统整体 | 系统 |
| 模块名 | 产品线里实际存在的模块 | 〈成本模块〉〈库存模块〉〈报表模块〉〈集成平台〉 |
| 客户名 | 客户简称，或「贵司」 | 〈客户简称〉 |

抽象名词不作主语，例如外部追问、取数成本、业务量、扩产、关键、源头、边界、口径、变动。

### 2.2 主语交替

相邻两页不用同一个主语。本页内容对应具体模块时用模块名，对应不上时用「系统」。

```
〈主数据模块〉可按多组织与多账簿分层扩展，不需重建账套
系统可在同一套主数据上支持四种经营模式
〈研发模块〉可控制物料与清单版本的生效范围
系统可在同一张委外工单上记录发料、回收与结算
```

### 2.3 客户名

讲客户自己的资产、组织或已有事实时写客户名。讲我方系统的能力时不写。

```
写      〈客户简称〉的自研执行系统保持不动，由本系统接收其回传结果
不写    系统可按多组织与多账簿分层扩展，不需重建账套
```

同一份材料里客户名可以出现多次。

### 2.4 情态词

本节适用于全部文字。

| 内容 | 写法 | 例 |
| --- | --- | --- |
| 我方系统的能力，没有在本客户验证过 | 用「可」 | 系统可按批次计算库龄 |
| 我方已在本客户验证过的事实 | 确定式 | — |
| 客户已有的事实 | 确定式，不加情态词 | 自研执行系统保持不动 |

### 2.5 数字

客户的经营数字和系统参数不进标题，数字放在页内。

```
不合格   计提比例已到 22%，要把识别时点从年末提到日常
不合格   〈库存模块〉可按批次计算库龄，并预测未来三个月的呆滞金额
合格     〈库存模块〉可按批次计算库龄并预测呆滞金额
```

分组数量词写在主语里可以保留，例如四种经营模式、三条产品线。这类数量词限定主语的范围。

### 2.6 长度

- 不超过 24 个汉字，单行。
- 最多一个逗号，两个分句的主语相同。

## 三、页内文字

### 3.1 分区小标题

小标题写这一区的具体内容。固定栏目名和设问句不用作小标题。同一个栏目名在多页重复时，读者每页都要重新猜它指什么。

```
不合格   〈产品名〉怎么实现          （设问，并在每页重复）
不合格   实现方式 / 对应做法        （固定栏目名）
合格     两套系统的分层对比
合格     四种经营模式的单据主线
合格     毛利变动的三个来源
```

### 3.2 导语

小标题写清楚后，导语通常多余，删掉。小标题没有交代分组名称时才写导语，并写全分组名称。

```
写      以下按研发设计、零件加工、批量制造、装备项目四种模式，分别说明单据主线与对应模块
不写    以下按四种经营模式分别说明        （分组名称没写全）
不写    毛利率是结果，不是原因            （没有分组，并且是判断句）
```

### 3.3 并列信息格

几格并排的信息区，每格分三层，不写成同色同字重的长段落。

| 层 | 内容 | 写法 |
| --- | --- | --- |
| 小标题 | 这一格讲什么 | 左对齐，20px，600，墨一 |
| 结论句 | 本格的一句结论 | 格内居中，20px，700，墨一 |
| 列表 | 可以逐条核对的事项，2 至 3 条 | 左对齐，18px，墨二 |

- 小标题按本页内容起。列头和小标题只用一种。
- 结论句是全格唯一的视觉重点。

### 3.4 列表与表格

- 列表只放能单独核对或反驳的事项。有先后依赖的步骤画成流程。
- 表格只用于两个以上对象的横向对比。单个对象的内容写成段落。
- 一页的信息块数量不限，版面放得下即可。

### 3.5 判断句与收尾句

页面不写作者的判断、提醒、风险提示和经验之谈。图和表画完，这一页就结束，页底不加总结句。

```
不写   边界不清是这类项目最常见的返工原因
不写   四种模式如果分散在不同系统，成本口径就无法合并看
不写   为什么这条要先谈
不写   关账前要拦住的两件事
```

这些内容属于口头讲解，写进讲稿。

### 3.6 「待确认」

给客户看的页面不写「待现场确认」「待补充」「待定」。需要向客户了解的内容写成问句，
并把这一列的列头或小标题写成「本次要了解的情况」，读者能看出这是议题。

```
不合格   各段工作分别占用多少人力，待现场确认
合格     各段工作分别占用多少人力，哪一段最影响月结时间
```

对内的调研提纲不受此限。

### 3.7 举例清单

方案和前期材料里列举几项时加「等」，避免读者理解为只有这几项。技术协议和工作说明书里的封闭清单写全，不加「等」。
举例挑最常用的几项。

```
不合格   物料、清单、工艺路线、成本对象，由总部统一定义
合格     物料、清单、客户、供应商等核心基础资料，可由总部统一定义
```

### 3.8 卡片文字

名词短语作卡片标题时，下面一行补全主语和动作。凑不出两层时合成一句话，不分标题和说明。

```
不合格   并存的三种成本对象
         工单、批次、项目
合格     工单、批次与项目三种成本对象可在同一账簿下并存，各产品线按自身模式取用
```

### 3.9 修饰语

一个动作最多带一个修饰语。

```
不合格   三大报表自动勾稽全量检查        （自动、勾稽、全量、检查四段叠加）
合格     三大报表一键生成，勾稽关系逐项自动核对
```

判断标准见 1.1 和第五节：行业实际使用的说法直接用，为表达顺畅拼出来的搭配不用。「勾稽」是会计用语，可以用；「全量检查」是拼出来的。
三个同类项并列不算叠加，例如「库龄分析、根因追溯、呆滞预测」。

## 四、图内文字

### 4.1 方框标签

方框标签可以是名词短语，但要是实际的单据名、业务对象名或系统模块名，并写完整的规范术语。

```
合格     财务报表 → 会计凭证 → 业务单据 → 单据附件
不合格   报表 → 凭证 → 业务单据 → 附件与接口记录
```

### 4.2 自造概念

图里不出现为表达顺畅临时造的名词。发现自造概念时，换成一个看得见的对象名，不换成动作名。

```
状态门        改为  〈清单〉版本状态       （对象名；不写「版本生效校验」这类动作名）
解耦点        改为  半成品缓存
净需求计算    改为  净需求                 （计划领域的标准说法）
```

### 4.3 卡片标题

卡片标题写动宾结构，不带主语和口语。省略的主语必须是本页标题里出现过的对象。

```
合格     统一库龄口径 / 追溯呆滞原因 / 预测呆滞金额
不合格   呆滞原因可以查到人                    （口语）
不合格   库龄口径 / 呆滞原因 / 呆滞预测        （名词短语，没有动词）
```

动词用日常动词。统一、追溯、预测、控制、保存本来就是动词，可以用。
标识、留存、赋权、归口是把名词当动词用，不用。凑不出日常动词时把标题写长一些。

```
不合格   标识关联方        改为  在客商档案标注关联方
不合格   留存定价依据      改为  保存定价依据与审批记录
```

### 4.4 并列项同级

几个框并排时，读者默认它们是同一层的同类对象。

```
不合格   业务层 / 数据层 / 分析层 / 接入层
         前三个是上下层关系，第四个横跨各层
合格     改为两列对比表：客户端、组织与账簿、数据库、报表取数、外部系统接入、技术支持，每行左右各写一个值
```

判断方法：给这组并列项起一个共同的上位名称，起不出来就不同级。

### 4.5 数字分布

一组并列项里只有一项带数字时，读者会以为这一项特别重要。每项都写可比的数字，或者都不写，数字放到页面其他位置。

```
不合格   票据台账    〈N〉张、〈M〉家出票人
         往来对账    客户与供应商余额、发票与收付款核销
合格     票据台账    应收票据与应收款项融资的登记、背书与贴现记录
```

## 五、通用措辞

判断标准是这个词在行业里是否实际使用。行业实际使用的说法直接用，不解释；为表达顺畅拼出来的搭配不用。

**词**

- IT 用语不进业务 PPT，例如上下文、下钻、心跳、埋点。
- 不借其他行业的词打比方，例如波次、地基、命脉、灰度、旁路、水位、抓手。业务读者读不懂这些词。
- 「形成」不当万能动词。实际是签署、登记、记录、取得还是生成，就写哪一个。
- 一个抽象词只有一个意思。「口径」这类词出现第二个意思时，换成具体的词。

**句**

- 单句不超过 60 字。一句一件事，写出谁做、做什么、做完的结果。
- 不为对仗删字。几个并列项字数接近时要检查，删掉的部分常常是区分意思的部分。

**结构**

- 自造的框架词，例如「五主线」「七域」「P0/P1」，首次出现时用一句话说明含义。说不清的框架拆掉重来。
- 不凑数。发现两条就写两条。
- 强调靠位置和留白，不靠满页加粗。
- 图表用一句话说明图里是什么，不教读者怎样读图。

**事实**

- 数得清的写数，数不清的说明原因。写「七类」「八个阶段」之前对着内容数一遍。
- 用了符号就配图例。
- 现状不等于目标。某事现在做得不好，推不出本期要把它做好。目标由客户定。
- 没调研到的内容在对内材料里写明，例如「夜班情况待调研」。给客户看的页面按 3.6 写成问句。

## 六、禁用清单

### 6.1 句式

| 类别 | 反例 |
| --- | --- |
| 格言 | 外部追问每年都会来 |
| 「不是 A，而是 B」及其变体 | 扩产要同时支持四种模式，不是把同一条产线复制一遍 |
| 比喻 | 订单到回款是一条链 |
| 反问和设问 | 先看架构撑不撑得住 |
| 祈使和建议 | 先把边界与口径定下来 |
| 抽象主语 | 工程数据的源头放在哪里，决定了…… |
| 评价人或团队 | 九个人管一家上市公司的账 |
| 无信息的垫话和收尾标签 | 值得注意的是、事实上、总而言之、一句话总结 |

### 6.2 词

承接、赋能、沉淀、落地、抓手、闭环、粒度、颗粒度、归集、收敛、下沉、对位、波次、地基、命脉、灰度、旁路、水位、卡位、
落库、对齐、原生、前置、全域、打通。

口语词：撑不撑得住、对得起来、说不清、准不准、记得住、跟得上、划得来、值不值、一条链、一盘棋、一本账、全量检查、
干活、坐下来、兜底、露馅、放水、做砸、硬推、松口、长什么样。客户原话里的口语保留，并标明是原话。

`check_deck.py` 内置以上词表，项目另有禁用词时写进 `项目配置.json` 的 `banned`。

## 七、交付前自查

阶段 8 执行，两项都做完再交付。

1. 只读标题：把全部标题抽成一列，从上往下读。逐项检查主语能否指认、相邻两页主语是否相同、字数是否超过 24、
   是否含数字、腔调是否一致。不合格的直接改。方案类对子标题做同样的检查。
2. 查禁用清单：按第六节逐项检索页面和讲稿。

## 八、新增规则

本文件的规则来自用户在实际页面上选定的例子。新增规则时，先找到用户否定过的原句写成反例，再写正例和判断方法。
